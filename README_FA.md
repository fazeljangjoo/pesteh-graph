# نقشه‌ی پروژه
1. یک ریپوی عمومی جدید بساز (مثلاً `pesteh-graph`) و این پوشه را در آن بریز.
2. در `.github/workflows/graph.yml` سه آدرس `YOUR_USER/...` را با ریپوهای واقعی عوض کن.
3. Settings → Pages → Source: شاخه‌ی main و پوشه‌ی `/docs`.
4. صفحه روی مانیتور باز بماند؛ هر دقیقه خودش graph.json را دوباره می‌خواند.
   بخش‌ها و اتصال‌های جدید (۷ روز اخیر) زرد و چشمک‌زن می‌شوند.
اجرای محلی: `python analyze.py --android A --windows W --web public_html -o docs/graph.json`

## وضعیت زنده‌ی سرور
1. `server/health.php` را روی هاست در `public_html/backend/api/` بگذار.
2. داخل فایل، `YOUR_USER.github.io` را با آدرس صفحه‌ی نقشه عوض کن.
3. در `docs/index.html` مقدار `HEALTH_URL` را چک کن.
هر ۳۰ ثانیه: حلقه‌ی سبز = سالم، قرمز = خراب، خاکستری = نامشخص (کنار نام، تاخیر به میلی‌ثانیه).

## صفحه‌ی تحلیل (`docs/stats.html`)
حجم کد، بزرگ‌ترین فایل‌ها، هاب‌ها، تفاوت ویندوز/اندروید، جدول‌های پرمصرف، فایل‌های بک‌اند بدون مصرف‌کننده، چرخه‌ی وابستگی و رشد در زمان.
`history.json` را Action هم کامیت می‌کند: در `graph.yml` خط `git add docs/graph.json` را به `git add docs/graph.json docs/history.json` تغییر بده.

## توضیح فارسی هر فایل
با کلیک روی هر گره، کارکرد فایل + اتصال‌هایش (به زبان ساده) + همسایه‌ها نمایش داده می‌شود.
منبع توضیح، به این ترتیب: ۱) توضیح هوش مصنوعی (`docs/descriptions.json`) ۲) کامنت فارسی داخل خود فایل ۳) خلاصه‌ی ساختاری که همیشه از روی گراف ساخته می‌شود.
برای فعال‌کردن توضیح هوش مصنوعی: در ریپوی نقشه، Settings → Secrets → Actions → کلید `ANTHROPIC_API_KEY` را بساز.
هر اجرا حداکثر ۱۵۰ فایل جدید/تغییرکرده را توضیح می‌دهد (برای اولین بار چند اجرا طول می‌کشد). اجرای محلی: `python describe.py --android A --windows W --web public_html`
توجه: کد فایل‌ها برای ساخت توضیح به API ارسال می‌شود؛ چون ریپوها عمومی‌اند مشکلی ندارد، ولی فایل‌های config/رمز هرگز خوانده نمی‌شوند.
